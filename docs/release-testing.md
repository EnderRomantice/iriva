# 上线前验证

本轮范围：学员、Host、运营流程；消息与练习重复提交；约谈并发；离线重试；PostgreSQL 幂等与容量。支付接入不在本轮范围，原有体验支付行为没有修改。

## 执行

需要本机 PostgreSQL，测试用户能够创建临时数据库和登录角色。测试编排只接受 loopback 地址，创建独立临时数据库、导入演示数据，并在完成后删除数据库与测试角色。不要把生产连接用于这些命令。

```sh
npm ci
npx playwright install chromium
export TEST_POSTGRES_ADMIN_URL=postgres://localhost:5432/postgres
npm run test:release
```

`test:release` 顺序运行类型检查、单元/接口测试、生产构建、PostgreSQL 合同测试、生产浏览器测试、HTTP 混合压测。任一步失败即返回非零退出码。没有 PostgreSQL 时必须失败，不能把跳过数据库测试理解为成功。

独立执行：

```sh
npm test
npm run test:postgres
npm run build
npm run test:e2e
npm run test:load
LOAD_CLIENTS=24 LOAD_MESSAGES=10000 LOAD_SECONDS=30 npm run test:load
```

如使用已安装的 Google Chrome，可设置 `PLAYWRIGHT_CHANNEL=chrome`。浏览器测试占用本机 3117 端口，压测占用 3118 端口，不复用现有服务。单独执行浏览器测试和压测前，需重新构建当前代码。

## 已实现的验证

- SQLite 业务规则与接口回归；独立 PostgreSQL 下的账号、Host 开通、审批、成员隔离和排课冲突。
- 两个数据库连接同时重放同一命令、24 个独立消息并发写入、事务回滚、受限角色与幂等表 RLS。
- 操作编号绑定账号、角色、空间和完整内容；字段排列顺序不影响重放。不同内容或空间复用编号返回 409。
- 生产构建中的真实 HttpOnly 会话：Host 创建任务 → 学员浏览器提交 → Host 浏览器发布反馈 → 学员与运营读取结果。
- 浏览器离线队列刷新恢复、消息及练习快速重复提交、Host 约谈重复确认、旧页面结论覆盖保护。
- 生产拒绝演示身份、跨账号队列和学员管理权限伪造。
- 401、408、425、429、503 保留待同步队列；真正的数据冲突仅阻塞对应实体；响应丢失后保持原操作编号。
- 账号草稿隔离；v13 备份导出/恢复；v12 回执恢复与旧版本四列回执写入兼容。

浏览器测试用测试库预建会话，不调用真实邮件供应商。验证码注册、过期、重放、冷却、失败发送由接口测试覆盖，邮件响应为测试替身。不能据此宣称真实邮件投递已验收。

## 压测模型和报告

生产 Next.js HTTP 服务 + 独立本地 PostgreSQL；80% 工作区读取、20% 独立消息写入，固定并发、无思考时间的闭环模型。默认 8 个客户端、1,000 条历史消息、15 秒；另有 20 个请求同时重放同一消息。测试核对每个成功写入的持久化数量和重放审计数量。

默认门槛：非预期错误率 < 0.1%，读取 P95 ≤ 800ms，写入 P95 ≤ 1500ms。报告含失败请求的耗时，不靠排除失败改善分位数。

产物：

- `test-results/load-report.json`：最近一次压测。
- `test-results/load-<并发>-<消息数>.json`：对应规模的最近一次压测。
- `test-results/load-server.log`：HTTP 服务日志。
- `playwright-report/index.html`：浏览器报告；失败截图和 trace 位于 `test-results/e2e/`。

这是单机诊断基准，不等同于线上容量。正式上线还需根据预计峰值和真实数据分布，在隔离预发环境完成 N/2N/3N 阶梯、至少两小时稳定性、真实网络断连、邮件投递及部署恢复演练。AI 供应商性能、成本和限流另行测试。

## 发布与兼容

先在预发应用并验证 `20261110074222_mutation_receipt_fingerprint.sql`，再部署新版本。该迁移增加独立的私有指纹表，启用 RLS，并仅给既有服务器角色授权；旧回执表列结构保持不变。SQLite 自动执行迁移 013。生产迁移沿用现有 `db:migrate:supabase -- --schema-only` 发布流程；本轮没有执行远程迁移或部署。

旧回执没有内容指纹，新版本收到这些旧操作编号时会返回 409，要求先核对结果，不会重新执行可能已成功的写入。旧版未绑定账号的浏览器草稿保留在 IndexedDB 中，不自动归属给当前登录账号；新草稿按账号、空间和角色保存。

已优化消息写入的目标行读取、会话权限查询，以及快照 JSON 聚合和字段转换。工作区快照仍包含全部可见消息，因此历史量增长的性能风险尚需持续跟踪；压测失败时应阻断容量验收，不能仅以功能测试通过宣布可投产。

## 2026-11-10 本地执行结果

最终 `test:release` 顺序执行通过：类型检查、生产构建、本地 75 项测试（另 2 项数据库专属测试在普通测试中跳过）、PostgreSQL 13 项测试、Chrome 浏览器 4 项测试、默认混合压测。独立 PostgreSQL 地址不可达时，命令已验证返回非零退出码。

| 本地闭环负载 | 请求数 | 非预期错误 | 读 P95 | 写 P95 | 判定 |
| --- | ---: | ---: | ---: | ---: | --- |
| 8 并发、1,000 条历史、15 秒 | 3,642 | 0 | 50ms | 61ms | 通过默认门槛 |
| 24 并发、10,000 条历史、30 秒 | 1,298 | 0 | 954ms | 809ms | 读取未达 800ms 门槛 |

## 2026-11-12 流量整改验收

本次针对 Shared Pooler Egress：运行时查询账号、登录校验、空间管理及写操作不再读取全库。数据库条件先做空间/角色/私聊权限过滤；集合默认 50 条、最大 100 条，消息以 `(created_at,id)` 游标读取。常规 DTO 不返回 Base64 头像。`read()` 在 production 直接拒绝，仅保留给开发种子、离线迁移及诊断工具。

- `/api/workspace/items` 支持权限内完整历史搜索和分页；消息、任务、报名、成员、频道/小组、Host/约谈等界面加入分页入口。搜索 300ms 防抖，AbortController 和请求代数防止旧响应覆盖新结果。月历按可见日期范围读取。
- 写操作读取目标及必要关联、冲突记录，容量校验和仪表盘进度使用 SQL 聚合。保留事务、幂等指纹、版本冲突与独立审计。
- 数据表触发器在同一事务中更新版本。条件 GET 在同一个数据库快照读取版本和数据，无变化返回 304；未提交事务、回滚、删除、权限撤销都有断言。版本变化时重新拉有界首屏并重新验证当前列表，**不是逐条变更流**；历史分页窗口可能重置。账号轮询已移除，多标签页同步通过浏览器锁及 IndexedDB 最近同步时间合并。
- 头像迁移到独立 `profile_avatars` 表，用户表仅保留引用。鉴权图片接口 `/api/avatars/[id]` 支持 ETag 和 private 浏览器缓存，新上传及不重新上传的资料修改已验证。Vercel 私有 Blob 创建被连接器以 403 拒绝，CLI 也未登录，**外部对象存储迁移未完成**。当前独立表仍使用数据库空间；图片仅在需要时单独读取，不随轮询返回。
- 本地增量检查发现并修复了分页合并错误和约谈旧请求覆盖乐观结果的问题；完整历史搜索截图位于 `test-results/history-search.png`。

最终执行：typecheck、生产 build、77 项普通测试（3 项 PostgreSQL 专属测试在此跳过）、16 项 PostgreSQL 测试、9 项 Chrome E2E 全部通过。数据库契约测试在一次性本地数据库中执行，压测未访问 Supabase 生产库。

| 本地闭环负载 | 请求数 | 非预期错误 | 读 P95 | 写 P95 | 判定 |
| --- | ---: | ---: | ---: | ---: | --- |
| 8 并发、1,000 条历史、15 秒 | 6,089 | 0 | 26ms | 43ms | 通过原门槛 |
| 24 并发、10,000 条历史、30 秒 | 10,456 | 0 | 78ms | 109ms | 通过原门槛 |

两档压测均对 20 次相同请求并发重放断言只产生一次副作用，成功写入数与数据库数量一致。压测使用无条件首屏 GET，未用 304 美化吞吐量。HTTP 平均首屏约 33 KB。

流量测试在 10,000 条历史消息及 620 KB Base64 头像样本下，用驱动返回行 JSON 字节衡量：旧全库读取 3,465,171 字节，有界首屏 26,699 字节，下降 **99.23%**；无变化同步读取 **621 字节**，HTTP 304 无响应正文。该指标不包括数据库协议开销，也不等同于已观察到的 Supabase 账单降幅。另一个租户头像增长不增加当前空间返回量；同时间戳游标、搜索字面 `%/_`、旧消息搜索、权限隔离与撤销均通过。

发布迁移为 `20261112021222_bounded_workspace_reads.sql`（SQLite 014）。必须先应用 schema，再部署应用。头像迁移以数据库事务复制后更新引用，没有删除图片；若回滚到旧应用，需要先在维护窗口从 `profile_avatars` 恢复用户表内的旧格式，以兼容旧前端。迁移历史和 checksum 不允许修改已应用文件。

当前尚不代表完成跨区域生产容量、两小时稳定性及外部对象存储验收。付款流程按本次范围未新增支付接入。
